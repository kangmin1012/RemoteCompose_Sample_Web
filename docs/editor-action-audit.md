# 에디터 액션 점검 (2026-09-26)

기준 프로젝트 `armcha/remotecompose`의 `index.html`과 현재 에디터를 비교했습니다. 기존 화면 전환, JSON 구조, 같은 부모 내 드래그 순서 변경, 클립보드 복사, GitHub 저장 흐름을 유지합니다. 화면 JSON과 배포 문서는 이번 수정에서 변경하지 않습니다.

## 수정한 오류

- 하위 삭제의 인라인 핸들러가 전역 함수 대신 버튼의 DOM `Node.removeChild()`를 호출했습니다. 기존 코드에서는 클릭 전후 하위 요소 수가 3개로 동일하고 TypeError가 발생하는 것을 브라우저와 DOM 환경에서 재현했습니다. 이제 충돌하지 않는 핸들러가 요소 경로로 삭제합니다.
- 깊이별로 나뉜 편집 코드 때문에 빈 하위 카드에 내용을 추가할 수 없었고 일부 중첩 테두리·액션·여백 속성을 편집할 수 없었습니다. 동일한 요소 렌더링/편집 함수를 모든 깊이에 적용합니다.
- 인덱스로 저장한 펼침 상태가 삭제·드래그 후 다른 요소를 가리켰습니다. 고유 ID로 펼침 상태를 유지하고 중복 입력 ID를 정리합니다.
- 따옴표가 HTML 입력 속성을 깨뜨렸습니다. 텍스트·속성 값을 이스케이프하고 0인 값도 그대로 표시합니다.
- 수정한 텍스트 요약·색상 코드가 갱신되지 않았습니다. 입력 중 포커스를 유지하면서 표시와 미리보기를 갱신합니다. 기본 테두리 색을 변경하지 않고 두께만 입력해도 적용됩니다.
- 펼치기 헤더가 키보드로 작동하지 않았습니다. Enter/Space를 지원하고 접힌 입력은 키보드 탐색에서 제외합니다.
- 초기화가 배경·스크롤·패딩을 남겼으며 늦게 도착한 초기 JSON이 편집 내용을 덮을 수 있었습니다. 초기 설정을 복원하고 변경 이후의 오래된 응답은 무시합니다.
- iframe이 에디터 스크립트보다 먼저 로드되면 `onPreviewLoad`가 없다는 오류가 발생했습니다. 핸들러 존재를 확인하고 에디터 초기화에서도 미리보기 전송을 예약합니다.
- 배포 요청 도중 화면을 전환하면 원래 파일에 다른 화면 내용이 저장될 수 있었습니다. 파일·화면 이름·JSON을 클릭 시점에 고정하고 저장 중 중복 제출을 막습니다.
- GitHub 조회 실패 후에도 저장을 시도하거나 다른 커밋의 Actions 결과를 표시할 수 있었습니다. HTTP 오류를 처리하고 저장 응답의 커밋 SHA에 해당하는 workflow만 추적합니다. 상태 조회 실패·시간 초과를 명시하고 이전 폴링이 새 배포 상태를 덮지 않게 합니다.
- 클립보드 복사 실패를 성공으로 표시하거나 브라우저 저장소 차단 시 전체 흐름이 멈추는 부분을 수정했습니다.

| 최상위 추가 6종 / 하위 추가 6종 | 실제 DOM 버튼 클릭 및 요소 수 확인 |
| 최상위·하위·중첩 삭제 | 실제 인라인 핸들러 클릭, 브라우저에서 삭제와 미리보기 반영 확인 |
| 속성 입력 | 한글·따옴표·액션·색상·테두리·0 반경·여백의 입력/재렌더링/JSON 확인 |
| 드래그 | 최상위·하위·중첩 같은 부모 내 순서 변경, 다른 부모 이동 방지, 펼침 상태 유지 |

| JSON 복사 | 실제 브라우저 복사 및 Unicode 내용 확인, 권한 실패/대체 복사 실패 처리 |
| 토큰 표시·숨기기 | DOM 버튼 클릭과 입력 유형 변경, 토큰 미입력 시 제출 차단 |
| GitHub 저장 | 요청 SHA·UTF-8 내용·대상 파일, 중복 클릭, 요청 중 화면 전환, 401/403/404/409/422 및 네트워크 오류 |
| 배포 상태 | 커밋 SHA 일치, 성공/실패·권한 오류·시간 초과·이전 요청 무시 |

`npm test`는 DOM 기반 회귀 테스트와 기존 JSON 직렬화 테스트를 실행합니다. GitHub 저장·상태 확인의 경계 상황은 가짜 응답으로 검증하며, 실제 배포 파이프라인은 커밋 푸시 후 GitHub Actions에서 확인합니다. 사용자 토큰으로 테스트용 화면을 배포하지 않습니다. 미리보기의 앱 내 클릭 액션 실행은 기존처럼 Android 호스트가 담당합니다.
